# 2026-10 运行时漏洞修复

同步自上游 [Sagit-chu/flvx#566](https://github.com/Sagit-chu/flvx/pull/566)，从 FLUX 3.3.17 起生效。

## 影响与修复

| 漏洞 | FLUX 涉及范围 | 修复 |
| --- | --- | --- |
| CVE-2026-111943（Go `crypto/x509` 中间证书信任） | 面板后端的版本检查、升级下载、授权验证，以及 agent 的更新下载、TLS 拨号与证书校验都使用 Go 标准库。原 Go 1.25 工具链缺少此修复。 | 三个 Go 模块最低版本升至 1.26.10；CI 与发版流程从 `go.mod` 读取 Go 版本；后端镜像使用 `golang:1.26.10-bookworm` 构建。 |
| CVE-2026-111497（Node.js Brotli 越界写入） | Node.js 只用于前端构建、开发和 skill 发布，不是面板的生产服务端（前端由 Nginx 提供静态文件）。CI 原使用已停止支持的 Node.js 20。 | `.node-version` 固定 22.23.4，CI 与前端镜像使用该版本；`package.json` 只接受已修复的 22.23.4+、24.22.1+、26.12.1+，前端开启 `engine-strict`。 |

Go 漏洞只涉及一组特定中间证书，并非拒绝所有长证书链。Go 1.27.0–1.27.2 同样未修复，手动使用 Go 1.27 时须为 1.27.3+。

上游同时排查了 PHP 漏洞 CVE-2026-109618、CVE-2026-109619：FLUX 不含 PHP 代码或运行时，无需处理；同机部署的其他 PHP 服务需单独排查。

## 让已部署的实例获得修复

Go 标准库编译在二进制里，只升级服务器上的 Go 或 `ca-certificates` 不会修复已有的面板和 agent，需要换成 3.3.17 或更新版本的发布产物：

1. **面板**：在“系统设置 → 更新与升级”升级到 3.3.17+，或在部署目录重新运行面板安装脚本并选择 `2` 更新。
2. **节点**：在“节点管理”中把所有节点的 agent 升级到同一版本，离线节点上线后也要升级。
3. **核对**：对二进制执行 `go version -m /path/to/gost` 或 `go version -m /path/to/paneld`，构建版本应为 `go1.26.10` 或更新。
4. **构建机**：自行构建时升级 Node.js 到 22.23.4、24.22.1+ 或 26.12.1+。运行静态前端的 Nginx 容器内无需安装 Node.js。
