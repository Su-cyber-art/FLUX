# FLUX 3.3.16

修复多落地地址规则的 UDP 转发可能中断最长 10 分钟的问题。

- 节点转发 UDP 时，会话空闲超时被正常回收也会被当成“目标失败”。面板为每条规则配置的是失败 1 次即排除 600 秒，因此填写了多个落地地址的规则，在会话陆续空闲结束后会把所有目标都排除，新的 UDP 会话报 “node not available” 收不到回包，直到排除时间过去。现在本端主动关闭的连接按正常结束处理，不再标记目标失败；目标真正拒收（例如端口未开放）时仍会被标记并切换到其他目标。
- 只填写一个落地地址的规则不受此问题影响。
- 移除节点选择时每次都向标准输出打印的调试日志，避免多目标规则在高并发下产生大量日志。

需要更新节点（agent）后生效。

验证：新增两条测试，使用真实的 UDP 监听器、选择器与面板相同的失败参数——会话空闲关闭后目标不被标记且新会话可正常转发（修复前失败、修复后通过），目标拒收时仍会被标记并切换到正常目标；两条测试在竞态检测下连续 20 次通过，`go-gost/x` 全部测试通过，节点程序编译成功。
