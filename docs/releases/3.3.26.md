# FLUX 3.3.26

同步上游 FLVX 3.0.1-rc8：relay 隧道开始逐跳认证，转发链缺失时拒绝改走直连；同时带来禁用用户时撤销隧道权限、UDP 回包源地址修复。

## relay 隧道安全

- **逐跳认证**：新建的隧道链路（relay 隧道，以及普通隧道转为 relay）默认启用认证。每个隧道有独立的凭据，保存在面板数据库中，每一跳都发送并校验对应凭据。之前不带凭据的请求也能经 relay 端口到达目标，相当于对外开放了一个代理。
- **缺链时拒绝连接**：入口和中继节点下发 `chain.strict`。编辑拓扑期间，如果某个节点的转发链暂时缺失或没有可用路由，连接会被直接拒绝。之前会改为从该节点直连目标，跳过后面的中继。
- **隧道操作排队执行**：同一隧道的创建、编辑、重部署和删除依次执行，不再交错。重部署不再先删除仍在使用的转发链，旧转发链等新的接收端确认后才移除。
- **待同步提示**：配置已保存但部分节点尚未确认时，接口返回 `runtimeStatus: "pending"`，前端显示警告。如果是关联转发下发失败，会附带每条转发的失败原因。
- **清理失败可恢复**：旧端点清理失败时，保留清理记录和端口占用，后续操作会重试，确认删除后才释放端口。新建隧道在等待远端确认前就预留本地端口。
- **联邦**：联邦对端需要具备相应的版本能力。面板会拒绝旧版对端、认证降级和私有凭据缺失的情况。等待远端确认时不再占用数据库事务。

## 其他修复

- **禁用用户时撤销访问**：禁用用户会撤销其隧道权限，并暂停该用户的每条转发。部分节点失败时，其余节点和转发继续处理，失败的节点汇总后供重试。编辑弹窗里会持续显示部分失败的提示。
- **UDP**：通配地址监听时，回包保留原目标地址作为源地址，不同目标地址的会话互相隔离。支持 IPv6 组播和链路本地地址（Linux）。

## 升级说明

本版本涉及面板和 Agent，**两端都要升级**。

- **升级前备份完整数据库**。面板自升级会自动备份，手动部署请自行备份。新的 relay 凭据只保存在数据库中，配置导出不包含凭据，受保护的隧道无法通过配置导入恢复。数据库备份包含凭据，需要妥善保管。
- **不要直接回滚到旧版面板**。旧版面板会重新下发不带认证的监听。如必须回滚，请同时恢复升级前的数据库备份。
- **已有隧道不会自动启用认证**。现有隧道保持 legacy 模式，行为和之前一样。只有新建隧道默认启用认证，目前没有自动迁移入口。需要保护现有 relay 端口时，请重建对应隧道。
- **Agent 必须同时升级**。旧版 Agent 会忽略 `chain.strict`，缺链时仍会改走直连。升级 Agent 后，在隧道页重新下发配置。
- 待同步状态说明配置已保存，但不代表所有节点都已生效。这段时间里旧的转发路径可能仍然存在，跨节点切换不是原子操作。
- 本次未解决的问题：使用 TCP、不校验对端证书的 TLS、默认 KCP 或不安全的控制链路时，relay 凭据仍可能被窃听。
- 隧道更新的待同步响应从 `data.runtimeSync.status` 改为 `data.runtimeStatus`，失败明细在 `data.failures`。直接调用 API 的脚本需要相应调整。

## 验证

本地后端完整测试（含新增的 relay 认证、隧道生命周期、端口预留、删除清理和联邦回归契约测试）、Agent 与协议模块测试、`go vet`，以及前端 TypeScript、生产构建和 ESLint 均通过。合并时 FLUX 与上游各自实现了隧道待同步反馈，现已统一为一种响应格式：沿用上游的处理流程，同时保留 FLUX 的逐条转发失败明细。竞态检测和 Linux UDP 网络命名空间回归由 CI 执行。
