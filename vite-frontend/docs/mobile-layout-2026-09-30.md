# 移动端布局修复

Mantine `Modal.Content` 会将直接传入的 `className` 同时合并到 `content` 和 `inner` 两个样式槽。此前的 `app-modal-content` 与各页面宽度类因此也修改了定位容器，加上按尺寸自动全屏的逻辑，造成手机上的偏移、宽度异常和内容裁切。

公共组件改用 `classNames.content`，定位容器只使用 `app-modal-viewport`。页面通过 `size` 指定桌面最大宽度，不再覆盖移动端几何样式。所有对话框都经过公共组件，包括快速搜索、验证码与升级进度。

`useVisualViewport` 将可见区域的高度、偏移写入 CSS 变量，安全区由 CSS 处理。缩放时保留原布局尺寸，继续支持用户放大查看。正文承担滚动，标题和底部操作区不参与滚动；单行和多行输入在触屏小窗口中最小为 16px。

3.2.2 补充焦点检查：可见视口缩小或字段获得焦点时，只滚动对应的弹窗正文，使当前输入框避开底部操作区。普通滚动事件不会反复调整焦点位置。长表单末尾字段在键盘模拟场景下额外验证。

规则和隧道共用 `DiagnosisResults`，保持原有延迟质量阈值与诊断接口。根据组件可用宽度切换卡片/横向排列，IPv6 带端口使用方括号显示，未分类结果也会保留。

验证使用外置盘上的临时 Playwright 工具与合成 API 数据，没有增加前端测试依赖或测试框架。WebKit 与 Chromium 分别执行了 83 项弹窗检查，包含六种屏幕尺寸、表单聚焦字体、可见视口缩小、居中位置和操作区可见性。额外检查长诊断内容滚动、关闭后的页面位置、旋转屏幕、选择弹层、浅色主题、监控记录横向滚动，以及 11 个业务路由的页面宽度。键盘测试模拟了可见视口变化；不等同于实体 iPhone Safari 验证。

后续新增弹窗请使用公共 Modal、ModalContent、ModalHeader、ModalBody、ModalFooter；不要向定位容器添加内容样式或在页面重新设置手机宽度。
